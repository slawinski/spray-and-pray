# Spray and Pray (SAP)

> A terminal-native, single-user job application engine. It tracks applications, generates AI-tailored, ATS-optimized CVs **and cover letters**, runs mock interviews, and turns interview weaknesses into interactive learning content.

**Spray and Pray** automates the most tedious parts of a job search so a solo job-seeker can focus on preparing and interviewing — not copy-pasting job descriptions and reformatting PDFs.

## What it does

SAP is a personal pipeline for the entire application lifecycle:

1. **Capture** a job posting (1-click from a browser extension, or a local JD file).
2. **Optimize** your Master CV and generate a matching cover letter — both tuned to pass Applicant Tracking Systems (ATS) while reading like a human wrote them.
3. **Track** every application through a status state machine (draft → applied → ghosted → interview N → offer → accepted/rejected).
4. **Prepare** with role-specific mock interviews, evaluated by an LLM with a readiness score.
5. **Learn** from your weaknesses with auto-generated, interactive lessons.

Everything runs locally. There is no backend service, no account, and no data leaves your machine except the LLM API calls.

## Features

### 1. ATS-Optimized CV Generation
- Takes a `master_cv.json` and a job description, produces a tailored CV in Markdown.
- Uses a dedicated LLM prompt (`cv_optimizer/prompts/optimize.md`) that enforces:
  - **Exact keyword matching** — literal string comparison against the JD (e.g. `React.js` not `React`).
  - **Anti-hallucination** — every skill and achievement must trace back to the Master CV. Gaps are never fabricated.
  - **Front-loaded keywords** in the Summary and first Experience bullets.
  - **Human readability first** — ATS passes get you screened, but a recruiter gets you hired.
- Renders a styled two-column PDF (header, sidebar with skills/contact, main column with experience/education).
- Optionally embeds a candidate photo (`candidate.jpeg`) top-left in the header, sized to match the name + title block.

### 2. ATS-Optimized Cover Letters
- Generates a tailored cover letter alongside the CV (`cv_optimizer/prompts/cover_letter.md`).
- 250–400 words, narrative prose with JD keywords woven naturally (not keyword-stuffed).
- Enforces ATS signals: exact role-title match, company-name personalization, front-loaded keywords, strong action verbs, no passive voice.
- Renders a clean, single-column letter PDF (name/contact header, date, `Re:` line, salutation, body, sign-off).
- Cover letters are generated by default whenever an application is tracked through the browser extension.

### 3. 1-Click Browser Extension
- Chrome/Firefox extension (Manifest V3, vanilla JS) that scrapes the current tab's job posting and POSTs it to the local API.
- Supports job boards with site-specific selectors plus a JSON-LD fallback:
  - LinkedIn, justjoin.it, nofluffjobs.com, theprotocol.it, greenhouse.io, workingnomads.com
- Generates **all files** — JD copy, CV (`.md` + `.pdf`), and cover letter (`.md` + `.pdf`) — on a single click.

### 4. Application Tracking
- SQLite database (WAL mode) persists every application with its status history.
- A status state machine with flow constraints prevents nonsense transitions (e.g. circular ghosted/applied toggling, "un-rejecting" an offer):
  - `draft` → `applied` → `ghosted` → `interview 1` → … → `interview N` → `offer` → `accepted` / `rejected`
  - Draft activation auto-inserts `ghosted` (pessimistic default).
  - Ghosted is replaced by any real outcome (interview/offer/rejected).
  - Backtracking (undo) is supported cleanly.
- Per-application filesystem directories (`applications/{company}_{role}_{id}/`) hold the JD, CV, and cover letter.

### 5. Terminal UI Dashboard
- Interactive Textual dashboard (`./cv-opt`) — no browser needed.
- Paginated, filterable table with a detail panel and a status bar.
- Full keyboard navigation (see [Usage](#usage)).

### 6. Sankey Funnel Visualization
- Aggregates application transitions into a funnel (`applied → interview 1 → … → offer → accepted`).
- Renders as an ASCII table in the terminal, or an interactive Plotly Sankey diagram in the browser.
- Ghosted entries are intelligently cleaned (transient ghosted periods are stripped; terminal ghosted kept).

### 7. Mock Interviews
- Generates role-specific questions (behavioral, technical, system design, coding) from the JD, Master CV, and optional `company_intel.json`.
- Browser-based interview session with a Monaco code editor, hint system, and progress bar.
- LLM evaluation produces per-question feedback, strengths/weaknesses, and a 0–100 readiness score.
- Weaknesses link to "Deep Dive" lessons (see below).

### 8. Learning Aide
- Generates blog-like interactive lessons from interview weaknesses (or any concept).
- Lessons embed live Monaco code editors, Chart.js charts, Mermaid diagrams, and interactive widgets.
- A persistent lesson library (`/learn`) and a D3.js knowledge graph (`/graph`) grow organically.

## How it works

### Core pipeline (CV + Cover Letter)

```
Browser Extension ──POST /api/track──▶ FastAPI server
                                        │
                                        ▼ (background task)
                              cv_optimizer.tracker.track()
                                        │
                        ┌───────────────┼────────────────┐
                        ▼               ▼                ▼
                 1. DB record     2. Copy JD to     3. Extract JD text
                 created          applications/     (PDF or plain text)
                                        │
                                        ▼
                              CVOptimizer (LLM) ──▶ optimized CV (.md)
                                        │
                                        ▼
                              PDFGenerator ──▶ styled 2-column CV (.pdf)
                                        │
                                        ▼
                              CoverLetterOptimizer (LLM) ──▶ cover letter (.md)
                                        │
                                        ▼
                              CoverLetterPDFGenerator ──▶ letter (.pdf)
                                        │
                                        ▼
                              DB updated + macOS + Discord notification
```

### Interview pipeline

```
TUI [P] ──▶ /prepare-interview/{app_id} ──▶ InterviewGenerator (LLM) ──▶ questions JSON
                                                                            │
                              /interview/{session_id} (browser, Monaco editor)
                                                                            │
                              answers saved ──▶ InterviewEvaluator (LLM) ──▶ scores + readiness
                                                                            │
                              weaknesses ──▶ generate_lesson (LLM) ──▶ interactive lesson
```

## Installation

### Prerequisites

- **Python 3.12+**
- A working **LLM API key** (DeepSeek by default, or any OpenAI-compatible endpoint)
- **macOS** (notifications and "Reveal in Finder" use `osascript` and `open`; other platforms will work but lose those conveniences)

### Steps

```bash
# 1. Clone and enter the repo
git clone <repo-url> spray-and-pray
cd spray-and-pray

# 2. Create a virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 3. Install dependencies (no requirements.txt — install directly)
pip install fastapi uvicorn jinja2 markdown pymupdf openai \
            pydantic python-dotenv unidecode requests textual

# 4. Configure environment
cp .env.example .env
#    Edit .env and set DEEPSEEK_API_KEY (and optionally DISCORD_WEBHOOK_URL)

# 5. Create your Master CV
cp master_cv.example.json master_cv.json
#    Fill in your real data (see Data model below)

# 6. (Optional) Add company interview intel
#    Create company_intel.json (see Data model below)
```

> **Note:** There is no `requirements.txt` or `pyproject.toml` — dependencies are managed ad hoc. If you want reproducible installs, consider pinning them with `pip freeze > requirements.txt`.

| Setting | Default | Description |

## Usage

### 1. Terminal dashboard

```bash
./cv-opt
# or: python3 cv_optimizer.py
```

| Key | Action |
|---|---|
| `q` | Quit |
| `r` | Refresh |
| `/` | Focus filter bar |
| `enter` | Toggle detail panel |
| `s` | Change status |
| `o` | Open application folder in Finder |
| `ctrl+r` | Re-generate CV |
| `ctrl+g` | Generate cover letter |
| `P` | Prepare mock interview (opens browser) |
| `L` | Open lesson library (browser) |
| `S` | Open Sankey funnel (browser) |
| `n` / `p` | Next / previous page |
| `T` | Set source (e.g. "Referral") |
| `u` | Open job posting URL |
| `J` | Run automated job discovery (background worker) |
| `D` | Delete application |
| `escape` | Dismiss modal / detail panel |

The application table shows a **Match** column (from `match-v2`): `85–100`
bold green, `70–84` yellow, `55–69` orange, `<55` dim red. Auto-discovered
applications show their `auto:<provider>` source. The detail panel splits
evidence into **Strong** (direct), **Transferable** (framework transfer —
e.g. "Svelte → React, Vue.js") and **Gaps**, plus discovery metadata
(posted/discovered dates, location, salary).

### 1b. Automated job discovery

```bash
./cv-opt discover              # fetch → dedupe → filter → score → import >=85
./cv-opt discover --preview    # no LLM calls, no imports (debug search config)
./cv-opt discover --no-import  # score + persist, no Draft creation
./cv-opt discover --source serpapi --max-scores 10
./cv-opt discover --rescore    # ignore the score cache
```

Discovery runs without FastAPI or the TUI — it talks to SQLite, the match
engine, and the source adapters directly. Runs are serialized with a
`.discovery.lock` file; a concurrent run prints `Discovery already in
progress.` and exits.

**Pipeline order (cost-optimized):** fetch → normalize → dedupe (source ID →
canonical URL → company/title/location + JD similarity) → cheap prefilter
(interns/juniors/backend-only/foreign-geography/short JDs) → prioritized
score queue (newest, highest-confidence first, capped at
`max_scores_per_run`) → `match-v2` → qualification → transactional Draft
import. Dedupe and filtering happen **before** any LLM call; unchanged
JD/candidate/scoring identities reuse cached assessments.

**Why Drafts, not `applied`?** A discovered job is not an application until
the user decides to pursue it. Qualifying jobs (`>= 85`, active, not
dismissed) become `draft` applications containing the JD and the copied
Match Assessment — but never a generated CV or cover letter, and never a
fake `applied` status. Document generation stays a deliberate, per-job user
action in the TUI (`ctrl+r`, `ctrl+g`).

**Sources**

| Source | Mechanism | Notes |
|---|---|---|
| `serpapi` | Google Jobs via SerpApi (`SERPAPI_API_KEY`) | Broad market source; role-centric queries, bounded pagination, 429-aware |
| `lever` | `api.lever.co/v0/postings/{site}?mode=json` | Configure `sources.lever.sites` |
| `ashby` | `api.ashbyhq.com/posting-api/job-board/{board}` | Compensation included; configure `sources.ashby.boards` |
| `greenhouse` | `boards-api.greenhouse.io/v1/boards/{board}/jobs` | Public boards; configure `sources.greenhouse.boards` |

One failing source never stops a run; rate-limited sources stop for that
run only.

**Dismissal & lifecycle.** Deleting an auto-imported Draft marks its
discovery record `dismissed`, so the next run does not re-import it.
Direct ATS postings missing from two consecutive polls become `inactive`
and are never auto-imported. Jobs below the threshold stay in
`job_postings` with their score, ready for reconsideration.

**Notifications.** One batched macOS + Discord summary fires only when new
Drafts were actually imported — never a "0 new jobs" message. Discord
failures never fail discovery.

**Scheduling (macOS).**

```bash
scripts/install_discovery_launchd.sh    # daily at 08:00 (no hardcoded paths)
scripts/uninstall_discovery_launchd.sh
```

The launch agent runs `<repo>/.venv/bin/python <repo>/cv_optimizer.py discover`.

### Database schema (`applications.db`)

| Table | Purpose |
|---|---|
| `applications` | One row per application: `company`, `role`, `jd_path`, `cv_path`, `cover_letter_path`, `job_url`, `source`, `created_at` |
| `status_history` | Ordered status transitions per application |
| `interview_sessions` | Mock interview questions, answers, scores, readiness |
| `lessons` | Generated lessons with content JSON, linked to sessions/apps |
| `job_postings` | Canonical discovered vacancies — separate from `applications` by design |
| `job_source_refs` | Per-source identities (`UNIQUE(source, external_id)`), enabling one posting ↔ many sources |
| `job_match_assessments` | Versioned `match-v2` scores per posting, with cache identity (candidate/JD/version/model) |
| `discovery_runs` | Run-level observability: counts, per-source stats, errors |

### Match Score v2 — framework transferability

The Match Score (docs/specs/MATCHING_SCORE_SPEC.md) gained a `match-v2`
scoring version with a new evidence taxonomy:

| Level | Value | Meaning |
|---|---|---|
| `direct` | 1.00 | Exact skill evidenced in the Master CV |
| `framework_transfer` | 0.92 | Named mainstream JS framework absent, but other mainstream JS framework production experience exists and the JD does not demand framework-specific depth |
| `strong_transfer` | 0.75 | Closely transferable non-framework evidence |
| `framework_depth_gap` | 0.60 | Exact framework depth is central to the role (e.g. "6+ years Angular") |
| `partial` | 0.40 | Some relevant evidence |
| `unknown` | 0.50 | Non-skill facts the CV cannot establish |
| `none` | 0.00 | No evidence — hard-gap caps still apply |

The framework family (React, Next.js, Preact, Vue, Nuxt, Angular, Svelte,
SvelteKit, Solid, SolidStart, Ember, Qwik, Lit + aliases) is validated in
Python: the LLM proposes a level, but only genuine JS-frontend-framework
names may receive `framework_transfer`/`framework_depth_gap`, and the
profile must evidence at least one *other* framework. React does not
"transfer" to Django or Kubernetes. Framework transfer never triggers the
missing-core hard caps (`<=69` / `<=54`); a genuinely absent independent
must-have still does. Historical `match-v1` rows remain stored and versioned.

## Testing

```bash
python3 -m pytest tests/ -q
```

Key suites:

- `tests/test_framework_transferability.py` — `match-v2` evidence taxonomy, framework-family validation, hard-cap interactions (no LLM calls)
- `tests/test_discovery_filters.py` — deterministic prefilter (geography/role/seniority/JD length)
- `tests/test_discovery_dedupe*.py` — URL normalization, fingerprints, cross-source merge, false-split protection
- `tests/test_discovery_sources.py` — fixture JSON → `DiscoveredJob` normalization for all four providers
- `tests/test_discovery_importer.py` — transactional Draft import, threshold, dismissal lifecycle
- `tests/test_discovery_integration.py` — end-to-end runs with a fake source and mocked LLM (cache, budget, isolation, modes)
- `tests/test_source_persistence.py` — `source` persistence + migration-from-existing-DB regressions

All provider network calls are mocked or fixture-backed; live integration
tests are intentionally opt-in.

## Constraints & limitations

- **Single-user, local-only.** No authentication, multi-tenancy, or remote hosting. The API binds to `localhost` and assumes one operator.
- **macOS-centric.** Notifications (`osascript`) and "Reveal in Finder" (`open -R`) are macOS-only. Other platforms work but lose those conveniences.
- **LLM dependency.** CV, cover letter, interview, and lesson generation all require a reachable LLM API and consume tokens (cost/time). Generation is synchronous in the TUI (`ctrl+r`, `ctrl+g`) and backgrounded in the server.
- **No dependency lockfile.** Dependencies are installed ad hoc; there is no `requirements.txt` or `pyproject.toml`. Pin them for reproducibility.
- **Personal data is gitignored.** `master_cv.json`, `applications.db`, and `applications/` are not version-controlled. Back them up yourself.
- **PDF layout is fragile.** The CV PDF uses hard-coded dimensions (A4 mediabox, fixed sidebar width). Large deviations in content length or diacritics may need layout tuning.
- **Anti-hallucination is prompt-enforced, not code-enforced.** Output correctness depends on the LLM following the prompt. Always review generated documents before submitting.
- **ATS optimization is heuristic.** "ATS-optimized" means following well-known parser heuristics (literal keyword matching, clean text, standard headings) — it does not guarantee passage through any specific ATS vendor.
- **Cover letter scope.** The cover letter generator assumes a generic "Dear Hiring Manager" salutation; it cannot infer a specific recruiter's name.

---

## Security & privacy

- **Your personal data** (name, phone, email, work history) is sent to the LLM provider in every generation request. Choose a provider you trust; this is the only place data leaves your machine.
- **CORS is fully open** (`allow_origins=["*"]`) to support the browser extension. Any website can POST to your local API while it's running. This is acceptable for a local single-user tool, but be aware that a malicious page could trigger generations. The server never exposes raw Master CV contents over HTTP — only the LLM pipeline and file-reveal endpoints.
- **No authentication** on the API. Do not expose port 8000 to the network.
- **Discord webhook** (if configured) receives success/failure summaries, including company/role names.
